# ADR-0003. SeaweedFS вместо MinIO для S3-хранилища

Дата: 2026-10-16 · Статус: принято

## Контекст

PRD (11.2) называет MinIO хранилищем файлов в self-hosted. На 2026-10-16 образы `minio/minio` и
`quay.io/minio/minio` недоступны: MinIO перестала публиковать сборки community-версии. Self-hosted Orbit
должен подниматься одной командой из публичных образов.

## Решение

Локальная разработка и self-hosted используют SeaweedFS (`chrislusf/seaweedfs`, Apache-2.0) со встроенным
S3-шлюзом. Сервер работает с хранилищем только через S3 API, поэтому реализация меняется без изменений кода.

## Рассмотренные варианты

- **RustFS** (Apache-2.0) — совместим с MinIO, но проект молодой.
- **Garage** (AGPL-3.0) — лёгкий, создан для self-hosted, но требует ручной настройки layout кластера.
- **SeaweedFS** — зрелый, один процесс, S3 включается флагом. Выбран.

## Последствия

- Учётные данные S3 задаются в `deploy/seaweedfs-s3.json`; бакет создаёт одноразовый `seaweedfs-init`.
- В публичном облаке по-прежнему можно использовать любой S3-совместимый сервис (российский S3).
