# ADR-0005. Секретные чаты на Olm

Дата: 2026-10-20 · Статус: принято

## Контекст

Эпик SCRUM-82 (PRD 3.1): личный чат, содержимое которого не видит сервер. Требования — шифрование на
устройстве, пересылка только шифротекста, привязка чата к устройству, таймер самоуничтожения и код
безопасности для сверки ключей. Клиент — web (`orbit-web`), позже Tauri. Свою криптографию не пишем;
начальный бандл расти не должен. Задача E2E-1 — выбрать протокол и зафиксировать решения, E2E-2…E2E-6
их реализуют.

## Решение

**Протокол.** Olm (libolm) через npm `@matrix-org/olm` 3.2.15 — WASM-сборка, Apache-2.0. Библиотека
загружается лениво, только когда открыт секретный чат, работает в Web Worker, wasm лежит в отдельном
chunk (`import()`), поэтому начальный бандл не растёт. Olm даёт X3DH-подобный handshake по pre-key,
Double Ratchet, one-time pre-keys, outbound/inbound-сессии, pickling для хранения и подписи ed25519.

**Устройство — это аккаунт Olm.** Одно устройство = один Olm account. Сервер хранит только публичные
identity keys (curve25519 для обмена, ed25519 для подписи), one-time pre-keys и непрозрачные конверты.
One-time key выдаётся один раз: `ClaimOneTimeKey` — это `DELETE … RETURNING`, два запроса не получат
один и тот же ключ. Секретный чат — пара устройств, а не аккаунтов: у человека с ноутбуком и телефоном
два разных чата с одним собеседником, истории между ними нет.

**Ключи на диске.** Pickles аккаунта и сессий Olm шифруются AES-GCM ключом, который держит
`PlatformAdapter` (web: IndexedDB, `shared/platform`; ADR-0004 в `orbit-web`); сборка Tauri будет
хранить ключ в keychain ОС. Расшифрованные сообщения, отметки о сверке и таймеры живут только в
IndexedDB этого устройства. Очистка данных браузера стирает чат — это ожидаемо и написано в UI.

**Конверт.** В `secret_envelopes` лежат только байты шифротекста (в БД `bytea`, в API base64),
устройства отправителя и получателя, тип 0/1, `created_at` и `expires_at`. В логах и метриках нет ни
текста, ни ключей, ни имён файлов. Доставка — по личному потоку WebSocket (`secret.envelope`);
подтверждение удаляет конверт, неподтверждённый живёт не больше 7 дней. Сообщения хранятся только в
IndexedDB; таблицы сообщений сервера секретный канал отвергают — `POST` и `GET` сообщений возвращают 404.

**Вложения.** Файл шифруется на клиенте свежим AES-256-GCM ключом и 12-байтным IV. Шифротекст идёт
через существующий `POST /api/v1/channels/{channelId}/attachments` в секретный канал под непрозрачным
именем; ключ и IV едут внутри зашифрованного конверта. Получатель скачивает шифротекст по подписанной
ссылке и расшифровывает локально. Сервер хранит дедлайн (не больше 7 дней) и удаляет просроченные
файлы sweeper'ом.

**Код безопасности.** Строится из публичных identity keys обоих устройств: 30 эмодзи (6 рядов по 5),
12 групп по 5 цифр (60 цифр) и QR-код. Сверка локальная. Смена ключа собеседника сбрасывает отметку и
показывает предупреждение; отправка неподтверждённому изменившемуся ключу требует подтверждения.

**Таймер.** Удаление на клиенте из IndexedDB плюс `expiresAt` на конверте и вложении на сервере. У
отправителя отсчёт с отправки, у получателя — с прочтения. Варианты: 5 с, 30 с, 1 мин, 1 ч, 1 день,
1 неделя.

**Честные ограничения web.** Скриншоты запретить нельзя. Код приходит с того же origin, поэтому
скомпрометированный сервер теоретически может отдать чужой JS; это снижают CSP, SRI, отсутствие
сторонних скриптов и путь Tauri, но не устраняют. Скомпрометированное устройство ломает E2EE. Сервер
видит метаданные: кто, с кем, когда, размер.

**Известные пробелы.** Любой аутентифицированный может вычерпать one-time keys устройства; rate
limiting и anti-abuse — отдельная задача. Синхронизации между устройствами нет. Групповых секретных
чатов нет.

## Рассмотренные варианты

- **libsignal** — нет официальной web/WASM-сборки; обёртка вокруг Rust-крейта — риск сопровождения и
  размера.
- **OpenMLS (MLS)** — спроектирован для групп, для 1:1 избыточен и крупнее; оставлен вариантом для
  групповых секретных чатов, вне эпика.
- **Olm** — выбран: WASM, зрелая схема для 1:1, pre-keys и ratchet из коробки.

## Последствия

- Новый модуль `internal/secrets`: `handler.go`, `service.go`, `store.go`, `sweeper.go`.
- Миграции `00011_secret_channel_kind.sql` (значение `secret` в `channel_kind`) и
  `00012_devices_and_secret_chats.sql` (`devices`, `device_one_time_keys`, `secret_chat_devices`,
  `secret_envelopes`, `attachments.channel_id` и `expires_at`).
- Новые операции API: `GET/POST /api/v1/devices`, `DELETE /api/v1/devices/{deviceId}`,
  `GET /api/v1/users/{userId}/devices`, `POST /api/v1/devices/{deviceId}/one-time-keys`,
  `GET /api/v1/devices/{deviceId}/key-bundle`, `GET/POST /api/v1/secret-chats`,
  `GET /api/v1/secret-chats/{secretChatId}`, `GET/POST /api/v1/secret-chats/{secretChatId}/envelopes`,
  `DELETE /api/v1/envelopes/{envelopeId}`. Устройство называется заголовком `X-Orbit-Device`.
- `internal/gateway`: личный поток (`SubscribeUser`, `pumpPersonalEvents`) и кадр `resume` с курсорами
  `conversations`; события `conversation.created` и `secret.envelope`. Конверты не реплеятся по `seq`
  (его у них нет): пропущенные забираются через `GET …/envelopes`.
- Web: Olm и wasm не попадают в начальный chunk; Worker и `PlatformAdapter` — E2E-3, интерфейс —
  E2E-4, таймер и сверка — E2E-5.
- Пределы: 10 устройств на аккаунт, 200 pending one-time keys на устройство, 100 ключей за загрузку,
  конверт ≤ 64 КиБ, TTL конверта и файла ≤ 7 дней, sweeper конвертов раз в 5 минут, файлов — раз в час.
  Гостевой аккаунт не может начать секретный чат (403).
- Security-ревью и чек-лист — задача E2E-6; модель угроз — `docs/threat-model-secret-chats.md`.
